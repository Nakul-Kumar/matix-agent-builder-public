SCOPE: Two related changes to the BLUEPRINTS section's runtime selection.

(1) Make the "Choose your setup" prompt visually obvious — right now it reads as a quiet caption.
(2) Hide everything below the three runtime tabs (the export row AND the blueprint content) on initial page load. They appear ONLY after the user clicks one of the three runtime cards (Codex / Claude Code / OpenClaw).

CHANGE 1 — PROMOTE THE "CHOOSE YOUR SETUP" PROMPT

Current state: small italic centered helper "Choose your setup — pick the runtime you want to build with." sitting just above the tab strip. Too quiet for what is now a required action.

Replace with a clearer call:

   Choose your runtime
   Pick one to see the blueprint.

Treatment:
- Line 1 ("Choose your runtime"): Fraunces serif, weight 600, 22px, --text-primary, centered.
- Line 2 ("Pick one to see the blueprint."): Fraunces italic 15px, --text-muted, centered, 4px gap below line 1.
- The whole lockup sits centered above the tab strip with 24px gap below.

Drop the previous italic caption. This two-line lockup replaces it entirely.

CHANGE 2 — GATE EVERYTHING BELOW THE TAB STRIP BEHIND A USER SELECTION

State management:
- The activeRuntime variable should initialize to null (or undefined), NOT to "codex". On initial render, no runtime is active.
- When activeRuntime === null:
   * All three runtime tab cards render in their inactive state — no terracotta border on any card, no inset highlight.
   * The export row (ANTHROPIC / CLAUDE CODE · BROWSER PROVIDER CALLS NO · ... · VIEW JSON · EXPORT SAFE BUNDLE) does NOT render.
   * The blueprint content below (the CODEX / CLAUDE CODE / OPENCLAW category label, agent title, and the 2×2 Skills/MCPs/Files/Reasons grid) does NOT render.
- When the user clicks any tab card:
   * activeRuntime updates to that runtime.
   * The clicked card receives the active state (terracotta border + inset).
   * The export row appears, with metadata bound to the active runtime.
   * The blueprint content appears below, also bound to the active runtime.
- Subsequent clicks switch activeRuntime; the content below updates in place. No re-mount, just data swap.

Reveal animation:
- When activeRuntime transitions from null → a runtime, fade in the export row and blueprint content (opacity 0 → 1, 200ms ease). Skip the fade if prefers-reduced-motion is set.
- When switching between runtimes (e.g. Codex → Claude Code), keep the existing 200ms opacity fade on the blueprint content — no full mount/unmount.

Empty-state cue (optional but recommended):
- When activeRuntime === null, render a single line of helper text in the space BELOW the tab strip where the export row would normally sit:
   "↑ Select a runtime above to load its blueprint and export bundle."
   Treatment: Fraunces italic 14px, --text-muted, centered, 40px vertical padding so the empty area has presence and the user clearly understands the section is waiting on them.
- The ↑ arrow character points up at the tab strip — gives the empty state a visual link to the action required.
- This helper disappears once activeRuntime is set.

Section navigator (the 01/02/03/04 side nav) behavior:
- Keep the side nav visible even when activeRuntime is null. The Blueprint item remains clickable — clicking it scrolls to the BLUEPRINTS heading (above the tab strip).
- License, Eval plan, Source link items continue to function as before.
