Restructure the BLUEPRINTS section (Section III on the results page) into a tab interface. The three runtimes (Codex, Claude Code, OpenClaw) become three clickable tab triggers at the top. Beneath the centered + enlarged "—— III. BLUEPRINTS" section header (with subtitle and count line), render a horizontal row of THREE tab triggers. Layout:

- Each tab trigger is a small Result-Card-styled element with these dimensions:
  - Width: 1/3 of the content area minus gaps (use flex: 1 within the container so they share width evenly).
  - Height: ~100px.
  - Background #14181C.
  - Border 1px solid #1F2429 when inactive, 1px solid #C2674A when active.
  - Border-radius 4px maximum.
  - Padding 14px.
  - Cursor pointer on all tabs (active or not — clicking the active tab is a no-op, but the cursor stays consistent).
  - Transition: border-color 160ms ease, background 160ms ease.

- Inside each tab trigger, vertical layout:
  - Top row: small mono caps category label "CODEX" / "CLAUDE CODE" / "OPENCLAW" — JetBrains Mono 10px, letter-spacing 0.16em.

    - Color when inactive: #6E6359.

    - Color when inactive: #6E6359.
  - The status portion ("● PREVIEW" / "● PLANNED" / "● EXPERIMENTAL") includes a small inline dot — terracotta primary on active, muted #6E6359 on inactive.

  - 2px inset box-shadow on the left edge: inset 2px 0 0 #C2674A (same as the Result Card hover treatment).
  - Optional: very subtle background tint shift to #181C20 (slightly lighter than inactive #14181C) so the active tab feels "raised."

  - Border becomes #2A3036 (slightly brighter than #1F2429).
  - Title color shifts to #EDE6DE.
  - No inset shadow on hover unless active.

Section 3 — Tab state management.

- State: a single activeRuntime variable in the parent component, defaulting to "codex" on results page mount.
- Click handler on each tab trigger sets activeRuntime to that runtime's slug ("codex" / "claude-code" / "openclaw").
- Render the blueprint content area conditionally based on activeRuntime. Either:
  - Mount only the active runtime's blueprint content (lazy approach — fastest), OR
  - Render all three but apply display: none to inactive ones (preserves scroll position within each runtime's boxes when the user switches back).
  Pick the lazy approach unless preserving per-runtime scroll position matters. Document the choice.

- Transition between tabs: when activeRuntime changes, fade the blueprint content area from opacity 0 to opacity 1 over 200ms. Use a CSS transition on opacity. The previous runtime's content fades out instantly when the swap happens — no crossfade, just an immediate hide then a 200ms fade-in on the new content. Keeps it snappy.

Section 4 — Keyboard accessibility.

- The three tab triggers should be focusable via Tab key (use button elements or add tabindex="0" + role="tab").
- Left/Right arrow keys cycle between tabs when the tab row has focus.
- Enter or Space activates the focused tab.
- Use ARIA: role="tablist" on the row, role="tab" + aria-selected on each trigger, role="tabpanel" + aria-labelledby on the blueprint content area.

Section 5 — Defaults and persistence.

- On initial results page render, activeRuntime defaults to "codex" (the first runtime).
- On tab switch, do NOT persist the choice to localStorage or URL state — fresh result builds always default back to Codex. Simpler, less state to manage.
