Two problems to fix. Do both.

PROBLEM A — Force a hard height constraint and real overflow

The likely cause: max-height was applied to an inner container, but the right column's parent grid cell has height: auto, so the cell grows to fit the cards and max-height never triggers. Replace max-height with a hard pixel height applied to the correct element.

Steps:

1. Locate the scroll container element (the wrapper around the four cards, NOT the "—— START FROM" header).

2. Apply these styles exactly to that container:
   height: 440px;
   max-height: 440px;
   overflow-y: scroll;
   overflow-x: hidden;
   padding-right: 8px;
   scrollbar-width: none;
   -ms-overflow-style: none;

3. Add a CSS rule to hide the webkit scrollbar on the scroll container:
   .scroll-container::-webkit-scrollbar { width: 0; height: 0; display: none; }
   (replace .scroll-container with the actual class/selector for your container)

4. The parent of this container (the right column itself) MUST NOT constrain height — let it remain height: auto. The hard height: 440px on the scroll container is what creates the overflow.

5. Apply the mask fade for soft top/bottom edges:
   mask-image: linear-gradient(to bottom, transparent 0%, black 8%, black 92%, transparent 100%);
   -webkit-mask-image: linear-gradient(to bottom, transparent 0%, black 8%, black 92%, transparent 100%);

6. Verify in browser DevTools:
   - Inspect the scroll container element.
   - In Computed Styles confirm height is 440px, overflow-y is scroll, overflow-x is hidden.
   - Run document.querySelector('YOUR_SELECTOR').scrollHeight in the console. It MUST be greater than 440. If it equals 440 or less, the children aren't filling enough vertical space — increase card min-height to 110px so the four cards plus gaps comfortably exceed 440px.
   - If scrollHeight is still ≤ 440 the container won't scroll. Adjust card heights until scrollHeight > 440.
